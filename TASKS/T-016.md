# T-016 - Despliegue Cloudflare y aceptacion HTTPS persistente

## Goal
Aplicacion web privada funcional en Cloudflare sin dependencia del Mac mini, conservando la version local.

## Why
Cumplir la ampliacion autorizada de O-005 sin confundir recursos creados con una aplicacion desplegada.

## Inputs
Adaptador T-015 validado; Worker, D1 UE y GitHub Actions dedicados. La version ed97eb4f-e231-40dd-a57e-63220a363da6 ya se subio. IDs y pruebas en docs/CLOUDFLARE_DEPLOYMENT.md.

## Outputs
T-016-output sera evidencia de version alojada, HTTPS real, acceso privado y persistencia remota. **Todavia no producido**: existe evidencia parcial del upload, no aceptacion final.

## Acceptance Criteria
Construccion/despliegue real exitoso, bind DB exclusivamente a xpo-load-studio-db, HTTPS verificado, autenticacion y limitador eficaces, datos sinteticos persistentes despues de nuevo despliegue, deduplicacion y logout, sin secretos/datos operativos expuestos. No contratar planes de pago.

## Verification
GitHub Actions run 39596676298 intento 2 PASS: version ed97eb4f-e231-40dd-a57e-63220a363da6, DB/ASSETS/LOGIN_LIMITER y 'No targets deployed'. Auditoria anterior run 39615897041 detecto binding plain_text y posterior audit 39616516566 intento 2 confirmo su rotacion a secret_text. Prueba HTTPS temporal run 39624025749 reporto GET /login HTTP 503 tras corregir bloqueo Cloudflare 1010 por cliente urllib, y run 39624439731 confirmo respuesta generica de clave ausente/no valida. Todos los ensayos confirmaron workers.dev y previews desactivados en finally. El secreto nunca se leyo. Workerd+D1 local PASS no equivale a aceptacion remota. Token de publicacion XPO ya existe y funciona; no pedir otro ni ampliar permisos sin error concreto.

## Evidence
Docs/CLOUDFLARE_DEPLOYMENT.md y runs 39596676298 (upload) / 39599178204 (auditoria de secretos y version). No contienen valores de secretos.

## Guardrails
No marcar DONE por tener un nombre de Worker o una URL asignada. No compartir tokens en chat. Mantener acceso cerrado hasta configurar el Secret. No fusionar PR automaticamente ni modificar otras aplicaciones.

## Failure / Recovery
Si la publicacion falla, conservar base y Worker; inspeccionar el build concreto. Corregir fallos reversibles y repetir pruebas. Si falla privacidad, deshabilitar rutas publicas de este Worker y registrar la causa. No borrar recursos o datos como atajo.

## Handoff
Accion minima operador: editar el valor de XPO_LOGIN_KEY como Secret en Cloudflare Production y asignar una clave NUEVA generada por gestor de contrasenas, 48+ caracteres y al menos 12 distintos (sin compartirla ni almacenarla en GitHub), Save/Deploy. Si existe XPO_LOGIN_KEY1 como Text antiguo, eliminarlo. Volver a ejecutar prueba HTTPS anonima de apertura temporal y cierre automatico antes de habilitar un dominio permanente. El controller repetira la auditoria de solo lectura; despues preparara una ruta HTTPS controlada y ejecutara la aceptacion remota con datos sinteticos. La conexion Cloudflare MCP mostro error interno; la auditoria segura se hizo con GitHub Actions, sin lectura del secreto.
